# Быстрые выпуски Promin

Обычный выпуск создаётся одной командой из чистой ветки `main`. Скрипт сверяет ветку с `promin/main`, меняет версию Tauri, создаёт коммит и тег, отправляет коммит в ветку, затем тег в репозиторий Promin. Он не использует upstream-репозиторий Stirling.

```bash
./scripts/release-promin.sh patch
```

Если установлен Task, тот же выпуск запускается так:

```bash
task release:promin -- patch
```

Для нового минорного или основного выпуска укажите `minor` или `major`. Перед публикацией можно посмотреть план без изменений:

```bash
./scripts/release-promin.sh patch --dry-run
```

После отправки тега GitHub Actions собирает macOS DMG и подписанный пакет автообновления, проверяет подпись и публикует GitHub Release. Ход сборки виден на вкладке **Actions** репозитория. При успехе пользователи получат обновление через встроенный updater; переустанавливать приложение вручную им не нужно.

Если нужно выпускать незавершённую работу, сначала оформите её отдельным коммитом и отправьте в `main`; релизная команда намеренно останавливается при незакоммиченных изменениях или расхождении с `promin/main`.

## Безопасность выпуска

- Не меняйте URL updater или публичный ключ подписи в `tauri.conf.json` без отдельной проверки.
- Не передавайте приватный ключ подписи в локальную команду: GitHub Actions читает его из repository secrets.
- Не создавайте повторно уже существующий тег. Если отправка оборвалась, сначала проверьте ветку и тег в `git status` и на GitHub.
